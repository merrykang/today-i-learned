# Lettuce ReadFrom: MASTER_PREFERRED → MASTER로 바꾼 이유

- `MASTER_PREFERRED`는 마스터 불가 시 replica로 폴백해서라도 읽음 → 승격 전 replica는 stale일 수 있어 세션성 데이터(토큰/요청정보)에 위험
- 폴백이 읽기를 조용히 성공시켜 **장애를 가림** → failover 테스트에서 클라이언트 복구 여부를 관찰할 수 없게 됨
- 가용성 / 데이터 최신성 / 테스트 목적, 세 축을 분리해 판단 → 이 서비스는 `MASTER`

교훈: "더 안전해 보이는" 설정이 맥락에 따라 반대가 된다. 읽기 정책은 데이터 특성(최신성 요구)과 운영 목적(장애를 드러낼 것인가)을 같이 놓고 골라야 한다.
